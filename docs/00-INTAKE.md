## Idea

**Name (working):** Data Analysis Agent

**The idea in 2 sentences:**
A multi-agent LangGraph pipeline that answers natural-language questions about any tabular dataset
(CSV/Excel/JSON) using an LLM for planning and interpretation and E2B sandboxes for code execution.
It returns grounded numeric answers plus charts — the numbers are computed by real pandas code, not
generated by the model.

**The problem it solves, and for whom:**
<!-- Frame as problem + who has it, NOT as the solution. -->
Technical users who want ad-hoc statistical answers and visualizations from a dataset have to write
pandas and matplotlib by hand every time, for questions they will ask once and never again. The
cost of the answer is dominated by boilerplate, not by thinking. Secondary user: Shreyansh himself,
who needed a non-trivial vehicle for hands-on agentic-systems work.

**Where did this come from?** Learning goal. Direct rep with LangGraph multi-agent orchestration,
structured outputs, eval frameworks, and provider abstraction — aimed at the AI/agentic-systems
line on his résumé. Personal pain was real but secondary.

**Why now — what wave is this riding?**
LLM code-generation plus sandboxed execution (E2B) matured enough in 2025–26 to make "ask a
question, get a computed answer" reliable rather than a demo trick. The unlock is not the model
writing pandas — it is being able to *run* that pandas safely and feed real output back, which
turns a plausible-sounding answer into a grounded one.

**The picks-and-shovels variant:**
The eval harness, not the agent — a framework for scoring LLM-generated analysis against
deterministic pandas ground-truth, usable by anyone building a data agent. Recorded honestly: this
was **not** compared before committing, because no intake was run. It is arguably the more
defensible artifact, and `evals/` turned out to be the part of this repo with the most reuse value.

## Success definition

**This project succeeds if:** a recruiter or technical reviewer can read the README, click the live
demo, upload any CSV, and get a correct grounded answer with a chart in under a minute — backed by
a public eval score, not a claim.

**Deadline for v0.1:** June 2026 *(retroactive: v0.1 shipped June 2026; v0.4 shipped July 2026)*

## Honest check

**Weekly hours I'll realistically give this:** ~10–12, in concentrated evening and weekend blocks.

**What's most likely to kill it?** **Scope creep** — and this is not hypothetical, it already
happened. V1 → V5 kept adding capability (parallel agents, eval framework, structured outputs,
provider abstraction, CI gate, UI polish, synthetic eval generation) instead of shipping and
stopping. Each addition was individually defensible; the aggregate is a project that was
demo-ready at V2 and is still accreting phases at V5. Logged as a lesson, not a ticked box: the
failure mode here is not abandonment, it is never declaring done. See the retro in
`06-ITERATE.md`.
